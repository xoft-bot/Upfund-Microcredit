## The actual problem (verified against current code, not assumed)

- `client/src/main.tsx`: an `admin` actor has `branchId: null` on their identity (admins are cross-branch by design). Today the *only* way an admin sees branch-scoped data is manually appending `?branchId=<uuid>` to the URL — there is a code comment saying exactly this. Every branch-scoped view (`AssignmentManager`, `ManagerVarianceDashboard`, the collections queue) inherits this gap for admin users.
- **There is no `GET /api/v1/branches` endpoint anywhere in `server/src/routes/`.** Nothing lists branches today. You need to add one.
- **The relevant data fetches in `main.tsx` run once, in a single `useEffect` at login**, keyed off the URL's `branchId` query param at that moment. They are not reactive to a later branch change. A real picker that lets someone switch branches mid-session requires making these fetches re-run when the selected branch changes — this is not just "add a `<select>`."

## Scope for this phase

1. **`GET /api/v1/branches`** (new route, follow the existing pattern in `server/src/routes/reconciliations.ts` — `authMiddleware` + `requireRoles` + the standard `{ ok, data, correlationId, version }` envelope). Admin gets every branch; every other role gets only their own `branch_id`'s row (so the same client code works for all roles without special-casing on the frontend).
2. **A `BranchSelector` component** in the shell header (`client/src/components/shell/` — check `GlobalSearch.tsx` there for the existing shell-component conventions and CSS classes). Visible only when the fetched branch list has more than one entry (i.e., effectively admin-only today, but don't hardcode that — key it off list length so it degrades correctly if that ever changes).
3. **Replace the URL-param hack with real React state** (`selectedBranchId` in `main.tsx`), but keep it reflected in the URL (`?branchId=`) so links stay shareable/bookmarkable — read the initial value from the URL, write back to it via `history.replaceState` or the router on change, don't add react-router as a new dependency if it's not already wired for this.
4. **Make the branch-scoped fetches reactive.** Specifically: the collections-queue fetch, the reconciliation-queue fetch, and — from Phase 1 — `AssignmentManager`'s own internal fetch (it already re-fetches on `branchId` prop change via its `useCallback`/`useEffect`, so for that one you just need to confirm `managerContext.branchId` now reflects the picker instead of always being `null` for admin). For the other two, this likely means moving their fetch logic out of the one-time login `useEffect` into something keyed on `[identity, selectedBranchId]`.
5. Do **not** touch the officer/collector/client-facing views — this phase is for roles that can act cross-branch (currently just `admin`; `manager` already has a fixed `branchId` and doesn't need a picker, but should still hit the new endpoint fine and just render nothing/a static label).
