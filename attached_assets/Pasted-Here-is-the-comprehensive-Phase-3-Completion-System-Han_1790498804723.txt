## 2. Phase 3 Concrete Execution Blueprint (Remaining Tasks)

To complete Phase 3 without duplicating existing endpoints or violating system invariants, implement the following technical steps in sequence:

### A. Materialized View for Dashboard Aggregation (`migrations/021_dashboard_performance_view.sql`)

To prevent heavy aggregate SQL queries on every page mount, wrap `reporting.ts` queries into a PostgreSQL Materialized View refreshed periodically via a lightweight worker or background trigger.

```sql
BEGIN;

CREATE MATERIALIZED VIEW IF NOT EXISTS mv_branch_portfolio_summary AS
SELECT 
  l.branch_id,
  COUNT(l.id) FILTER (WHERE l.status = 'active') AS active_loans_count,
  COALESCE(SUM(l.outstanding_principal) FILTER (WHERE l.status = 'active'), 0) AS total_active_portfolio,
  COUNT(l.id) FILTER (WHERE l.status = 'overdue') AS overdue_loans_count,
  COALESCE(SUM(l.outstanding_principal) FILTER (WHERE l.status = 'overdue'), 0) AS total_at_risk,
  COUNT(a.id) FILTER (WHERE a.status = 'pending') AS pending_applications_count,
  COALESCE(SUM(a.requested_amount) FILTER (WHERE a.status = 'pending'), 0) AS pending_disbursements,
  now() AS refreshed_at
FROM loans l
LEFT JOIN loan_applications a ON a.branch_id = l.branch_id
GROUP BY l.branch_id;

CREATE UNIQUE INDEX IF NOT EXISTS idx_mv_branch_portfolio_summary_branch 
ON mv_branch_portfolio_summary (branch_id);

COMMIT;

```

## 3. Strict Operating Invariants (Rules Carried Forward)

1. **Immutable Core Financial Engine:** Do NOT modify `payment-posting.ts`, `reconciliation-posting.ts`, `ledger.ts`, or `schedule.ts`.
2. **Service Worker Invalidation:** The browser service worker caches static assets aggressively. After running `firebase-tools deploy`, developers and QA testers MUST unregister the service worker via DevTools (`Application` $\rightarrow$ `Service Workers` $\rightarrow$ `Unregister`) and perform a hard reload.
3. **Server-Side Authority for Counts:** UI components MUST NOT perform client-side array length counts for summary cards. All counts must originate from `GET /api/v1/queues/counts` or `reporting.ts`.
4. **UUID Type Integrity:** All `correlation_id` values generated across client or server services MUST conform to valid UUID v4 formats. Prefixed strings (e.g., `lifecycle-corr-<uuid>`) cause PostgreSQL cast exceptions on `uuid`-typed columns (`audit_events`, `ledger_transactions`).
5. **No Blind PAR Threshold Overrides:** The threshold config in `par_threshold_config` defaults to 30/60/90 days. Non-default values may only be written via the `PATCH /api/v1/reporting/par-thresholds` endpoint by an `accountant` or `admin` user after explicit business sign-off.
