## 2. Decisions made this round (flagging for anyone reviewing later)

- **`CollectorReportingDashboard` was retired, not reused.** It was wired to `isOfficer` in the old `PortalDashboard`, not `isCollector` — despite the name. Neither role's spec'd nav has a slot for a full dashboard like it. It was unimported (not deleted) pending confirmation this was the right call; if someone decides its data belongs in the collector experience after all, it's still in the repo.
- **The old portal's metrics strip (Clients/Applications/Active loans/Outstanding) was dropped, not migrated** — it read from `getPortalOverview()`, not `/queues/counts`, so per the "no client-side counting" rule it doesn't get a new home.
- **Open item, not yet resolved:** `getReconciliationQueue` behaves like a queue of *open* batches only. If "accountant evidence" is meant to include already-decided batches for audit purposes (not just pending ones), that needs a broader endpoint — the accountant view built this phase only shows what the existing queue endpoint returns.

## 4. New workflow note this round

**A deploy landing doesn't mean an already-open tab shows it.** After `firebase-tools deploy` succeeds, a browser tab that was open before the deploy can keep running the previous service worker (`sw.js`) indefinitely — a hard refresh alone doesn't force it to hand control to the new version. Fix: DevTools → Application → Service Workers → Unregister, then fully close and reopen the tab. Worth adding to the QA checklist as a standard step after every deploy, not just when something looks wrong.

Also from this round: `git mv` on a file that was never `git add`ed fails with `fatal: not under version control` — use a plain `mv` (or `git add` first) for brand-new untracked files.
